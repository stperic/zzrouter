- Hybrid fit uses one conservative float32 convolution/SSM formula; allocated state rows belong in schema metadata, never engine-name branches in Go. Lab 2026-10-16: llama.cpp b10549 logged exactly the predicted KV (2048 MiB) and RS (598.5 MiB, 4 slots). vLLM 0.29 refuses to start unless its pool holds max-num-seqs blocks of one layer group each (compilation.py "exceeds available Mamba cache blocks"; group size is a heuristic in kv_cache_utils.py), so vLLM declares no rows and its hybrids stay unknown; a need-sized fraction that omits that pool makes the launch fail.
- Explainable fit follows the binding Decisions in docs/plan_explainable-fit.md: thirteen causes, weights_mib and unknown capacity evidence only; preserve decisions and use engine reports at the requested context for concurrency claims.
- Agent campaign prompts state the task and the RESULT format only. A prompt that names the tools to use, what to explain or what not to retry hides the confusion it measures (explainable-fit, 2026-10-16). Baseline -> after on that scenario: Codex went from a concurrency claim taken from its own `parallel` setting to vLLM's reported figure once `unknown_cause` and weights/capacity evidence existed.
- A test that asserts something has NOT happened yet must wait on a live deadline, never a pre-cancelled context: select picks randomly among ready cases, so a wrongly closed channel is caught only half the time (server-tests arc, 2026-10-16; mutation-check such waits). After that arc, most internal/server test time is building a server per test, mainly MCP tool registration, which is production code.
- Adding a provider must not change the interface other providers expose (user, 2026-10-16, Strata review). A new provider uses the existing catalog identity, resolver and MCP tools; a general defect it uncovers (sync overwriting a worker's enable, Responses-stream model echo, same-name collisions) gets its own change for every provider, never a provider opt-in or a new identity scheme. MCP inner requests pass through `dropCoordinatorHeaders`, so an `X-zzrouter-*` routing hint can never select anything from a tool.
- Run capacity follows docs/plan_run-capacity.md Decisions: six optional engine observations, per-pool kv_tokens, no aggregates or launch decisions; absent cache is unknown on protocol-13 peers.
- A worker's provider tree is the coordinator's cache, rewritten on every sync, so state that belongs to one node lives in the coordinator's tree under `nodes.<node>` and a worker asks the coordinator to write it (per-node enable, 2026-10-17; the user chose per node over cluster-wide because the MCP tools already promised it). A file is the coordinator's copy only on a worker (`s.node.IsWorker()`, the check `HandleProviderSync` uses; `Server.IsWorker()` follows the runtime role) and only for a provider the sync carries (`ServiceConfig.SyncedToWorkers`): cloud providers and registries never sync, so a worker owns those. A synced provider's pin is not node state: the coordinator holds one for every node, and `?node=` with a pin answers 400 `pin_is_cluster_wide` (2026-10-17).
- A transition zzRouter commanded is never an exit: an OS-manager observation that overlaps a control attributes nothing, and after a commanded start the observed state is unknown until something observes it, because launchd's pgrep cannot tell "not spawned yet" from "exited" (service-control job, 2026-10-17). Only `Registry.Cancel` carries `jobs.ErrCanceled`; a watcher stops its run or service only on that cause, never on a reap or terminal transition.
- The server reads provider config only through `AppsConfigStore.Config()` (`Server.appsConfig()`), and `mutate` is copy-on-write, so a config once handed out never changes: never cache that pointer or edit it outside the store (2026-10-17: a cached copy swapped by a store listener raced under concurrent provider syncs). A test server needs a store too (`config.NewMemoryAppsConfigStore`), or it skips request defaults, which every real node runs.
- To test that something did NOT wait, check the state its wait would have ended, never a wall-clock bound. The hung-worker enable test checks the sync round is still open (a non-blocking read of the fan-out's idle channel) instead of "under half the push timeout", which failed a slow Windows -race runner (2026-10-17). A dropped-connection signal let the regression through, so mutation-check the signal you pick.
- Engine processes never receive `LD_LIBRARY_PATH` or any other entry of `dangerousEnvVars`: `process.ChildEnvironment` refuses them (`pkg/prov_apps/process/security.go`), so a provider whose engine needs extra library directories must find them itself, as Strata's server does by applying `lib_dirs` from its own build metadata to its engine child (2026-10-17, Strata on-demand review).
- Slow per-model work, such as converting or packing weights, never runs in `prepareRun` or `process.CommandBuilder.Build`. A cold start holds the provider install gate and a catalog permit while it prepares, model deletion takes every permit, the run job does not exist yet, and `Build` also runs for parameters-status checks and previews (`processEngine.prepare`). Do it inside the engine's own start-up, for example a provider launcher, or after the run job exists (2026-10-17, two cold reviews of the Strata on-demand draft).
- A launch checks every parameter it passes (all tiers, after the selected runtime's exclusions, before feature injection) with `schema.Check`, the rule set PATCH also calls after its JSON-type gate (run parameters, 2026-10-17). The launch merge (`resolveRawLaunchParams`) keys parameters by flag name (`runsettings.FlagName`), so `ctx_size` overrides a configured `ctx-size`; a feature's `flag` is declared by the one schema builder (`providerSchema`, enum auto/false); a request key the runtime excludes (`runtime.exclude_parameters` or a feature's) is refused, a configured one dropped. Test managers built without `WithProviderSchema` get only the Go spine plus run settings, so a fixture declares its keys (`declaredSchema`, `memoryBudgetSchema`, `tierParameters` in pkg/prov_apps tests). Round 2: the resolver walk itself keys by flag name (`config.LayParameters`), so the later map wins whatever either spelled and each value keeps its stored `Key` for refusals and views; disagreeing spellings in one map are `duplicate_flag`, a declared request key the runtime lacks is `excluded_by_runtime`. A preview resolves on the node that runs it, as a start does (no coordinator pre-merge). An integral JSON number becomes an integer literal once (`schema.Canonical`). Round 3: a PATCH addresses the flag (`config.SetParameter`/`DeleteParameter` replace every spelling). A test must not `onDemandStarts.Wait()` while a queued run can still admit (WaitGroup Add after Wait races); wait on run state.
- A bool the engine also spells `--no-<flag>` is one key: schema.yaml marks it `negatable`, `false` renders `--no-<flag>` and a `no-<flag>` key is `unknown_flag` naming `<flag>: false` (run parameters round 2, 2026-10-17). Verify pairs from source, not `--help`: llama.cpp b10549 declares them as `common_arg({pos}, {neg}, ...)` in common/arg.cpp; every vLLM 0.29 dataclass bool is `BooleanOptionalAction` (arg_utils.py `_compute_kwargs`) but explicit `store_true` flags such as `--disable-log-stats` are not. An `enum` bounds a value of any type, numbers included.
- A worker's catalog notice (`POST /internal/models/refresh`) refreshes only that worker: `Cache.RefreshNode` re-reads the node `certifiedWorker` names and splices it into the published catalog, and an unidentified notice is 403 (2026-10-18). Never answer a worker's request on a whole-cluster broadcast: the old notice rebuilt the cluster catalog before it answered, so one worker that was up but hung made every provider-sync push to a healthy worker time out and its enable answer 503 `provider_sync_pending`. A provider-sync push publishes only when it changed something. Known limits: a changed push whose notice fails leaves the coordinator's view of that worker stale and unflagged, since the next push is unchanged (a failed store reload has the same flaw); a worker renamed in `node.yaml` that has not re-paired is keyed by its old certificate name on a scoped read and by its new name on a full one, so it can be listed twice until it re-pairs.
- A test rig whose coordinator really probes a worker (`Connector.attemptConnection`) must fake that worker's `/internal/version`: a plain test build reports `0.0.0-dev`, which `CheckCompatibility` refuses below `ClusterCompatibility.MinSupportedVersion` (0.1.0), although the version matrix calls that floor informational. Keep the rest of the rig real (TLS servers, a hung TCP listener for a sleeping worker); the in-process transport an implementer's sandbox needed skipped the connection-level hang (2026-10-18).
- `golangci-lint`'s contextcheck verdict can flip with a stale cache: after a change elsewhere, nolintlint reported a needed `//nolint:contextcheck` as unused, and removing it made contextcheck fire. Run `golangci-lint cache clean` before acting on an "unused directive" report (2026-10-18).
