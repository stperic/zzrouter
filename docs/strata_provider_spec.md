# Strata provider

Strata is a Linux amd64 on-demand provider for `qwen4exp` GGUF models on NVIDIA GPUs. The shipped template starts disabled and carries a soft release seed, `0.1.44.1`. Explicit install versions override the seed; upgrades can follow upstream releases. The design record is [Strata on-demand](plan_strata_on_demand.md).

The installer builds Niko1221/Strata into `providers/strata/releases/<version>` using upstream's engine build and a private Python environment. It verifies `engine/strata --families` before preparing the shared MTP draft layer or refreshing its vocabulary, writes the embedded `bin/strata-launch`, then activates the verified release. Completeness includes the managed marker, version, engine, Python, server, MTP layer and the launcher's digest. A launcher from another zzRouter build reports drift and requires reinstalling Strata. Uninstall detaches management while retaining releases, packs and shared data. The installer retains its release-switch rollback implementation; no coordinator rollback route is exposed.

Agents use the ordinary `zz_provider_install`, `zz_model_download`, `zz_run_start`, `zz_job`, `zz_chat` and `zz_run_stop` tools. Models belong to the model store. At launch, `strata-launch` builds or reuses a pack under `data/packs`, writes a per-run server config and executes Strata's server. Pack work occurs inside the run, so cancellation and failure logs follow the normal process lifecycle. The node owns shutdown of the whole Unix process group, including escalation within the provider's shutdown timeout.

`capabilities.architectures: [qwen4exp]` selects Strata over format-only GGUF engines. Catalog evidence comes from shard 1's `general.architecture`, ahead of Hugging Face metadata. Explicit incompatible selections receive `architecture_unsupported` only when architecture filtering caused the exclusion. Unknown architecture remains eligible for explicit selection and storage admission. Cluster protocol 16 is required.

The template declares Chat Completions, stateless Responses and built-in tools. Messages uses the existing compatibility path. Readiness includes a chat probe with a 900-second window for cold packing and loading. The old external Strata template is archived at startup; Strata no longer runs as a managed daemon.

Phase 0 verified packing, chat, tools, Responses, Messages and group shutdown on `localai`. Full on-demand acceptance remains: download and switch Flash-Next and Swift models through MCP, check speed against the baseline, concurrent runs, and `/health` during long prefill. Remove the Phase 0 launcher copy before acceptance. Windows group waiting remains PID-based; Strata is Linux-only.
